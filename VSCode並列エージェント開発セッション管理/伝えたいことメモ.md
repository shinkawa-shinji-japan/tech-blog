# 伝えたいことメモ（前回の会話から整理）

## 記事の動機・背景

- VS Code の 2026年1月アップデート (v1.109) で、サイドバーにセッション履歴が表示されるようになった
- これが個人的に、並列でタスクを進める上でかなり役立っている
- Zenn のブログで紹介する記事を書きたい

---

## 伝えたい主要ポイント

### 1. セッション履歴UIの何が良いか

- 今まで履歴を見るのが分かりづらかったが、ボタン一つでセッション履歴を出せるようになった
- チャット画面の右側にセッション履歴が表示される
- 履歴のセッション項目をクリックすると、その時のセッションの会話にスムーズに移れる
- 全てのセッションの履歴を素早く行き来できる

### 2. 並列タスクの実践ワークフロー

- プロジェクトのタスクがいくつかある場合の流れ：
  1. タスクの要件を確認する
  2. どのブランチから作業するかを決める
  3. コードベース検索・公式サイト情報で情報収集して計画を立てる
  4. ↑ ここまでエージェントが自律的にできる（精度は課題かもしれないが、やってくれる）
  5. 人間が計画を承認したら、実装 → 動作確認 → PRドラフト作成まで任せられる
- コンフリクトしないタスク同士であれば、タスクごとの指示書を用意して5〜6個一気にセッションを立ち上げてどんどん任せていける

### 3. エージェントの状態が可視化されている

- 作業中 → 作業中のアイコンが表示される
- 作業完了 → 完了済みとわかる表示に変わる
- 承認待ち・コマンド許可待ち → それもわかるようになっている
- VS Code内でタスク1の動作確認をしながら、タスク2のコマンド承認を脇で行うといった操作がしやすい

### 4. マルチルートワークスペースの制約（正直に書く）

- 1つのVS Codeウィンドウでマルチルートワークスペースは現状難しい
- メインのルートワークスペースにしかコード編集権限が渡されない事象が発生する
- 他のワークスペースへの作業指示でも「編集権限がない」とエラーになる
- → 今のところ1プロジェクト＝1 VS Codeウィンドウが必要
- イケてないと感じているが、それ以外は非常に良い

## Claude Code ユーザーへの訴求ポイント（前回の調査結果）

- Claude Code で並列タスクを実現するには tmux + git worktree + Max プラン ($100/月) が実質必須
- Tmux はWindows非対応（WSL必要）
- セッション管理UIがなく、ターミナルを目視確認するしかない
- サードパーティツール (Parallel Code, ntm, agent-deck 等) が大量に生まれている ＝ 公式だけでは解決できていない証拠
- VS Code のセッション管理は GUI + エディタ統合 + 追加コストなしでこれを解決している
