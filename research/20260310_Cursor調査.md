## Cursor と GitHub Copilot の比較リサーチ（2026-03-10）

本ドキュメントは、IDE 内での操作感を中心に **Cursor** と **GitHub Copilot** を比較したメモです。記述は 2026-03 時点の公式ドキュメントに基づきます。

**凡例:** 〇＝標準で充実 / △＝できるが限定的 or 工夫が必要 / ×＝ほぼ不可 or 未対応レベル

## 1. IDE 内の操作感の比較

- **チャット／セッション管理**
  - **Cursor**
    - Agent ベースのチャット UI。エディタとエージェントの行き来が少なく、AI エージェント駆動開発に最適化されている。
    - チャットのフォーク（分岐）、複数セッションの管理ビューなどがあり、長い会話を整理しやすい。
  - **GitHub Copilot（VS Code 前提）**
    - VS Code の Chat ビューで複数のセッションを並行管理。セッションのフォーク、チェックポイント、別ウィンドウ表示、JSON エクスポートなどが可能。
    - 参考: [Manage chat sessions（VS Code Docs）](https://code.visualstudio.com/docs/copilot/chat/chat-sessions)
- **エージェント実行体験**
  - **Cursor**
    - Editor 内から Agent を呼び出し、コード探索 → 編集 → ターミナル実行までを一気通貫で扱う UX。
    - 参考: [Agent mode | Cursor Docs](https://cursor.com/help/ai-features/agent)
  - **GitHub Copilot**
    - VS Code 側の「Agent mode」により、ローカル／バックグラウンド／クラウドセッションを選びつつ作業できる。
    - GitHub 上では「Copilot coding agent」として Issue から PR までを非同期に自動化するエージェントも提供。
    - 参考: [Using agents in VS Code](https://code.visualstudio.com/docs/copilot/agents/overview), [About GitHub Copilot coding agent](https://docs.github.com/en/copilot/concepts/coding-agent/coding-agent), [GitHub newsroom: Coding agent for GitHub Copilot](https://github.com/newsroom/press-releases/coding-agent-for-github-copilot)
- **ブラウザ操作・Web UI テスト**
  - **Cursor**
    - Agent がブラウザを開き、ページ遷移・要素クリック・フォーム入力・スクリーンショットなどを実行可能。
    - エディタから離れずにフロントエンドの確認・デバッグができる。
    - 参考: [Browser use | Cursor Docs](https://cursor.com/help/ai-features/browser)
  - **GitHub Copilot（VS Code）**
    - 「Browser agent tools」により、統合ブラウザを AI エージェントが操作可能（実験的機能）。
    - `openBrowserPage` / `clickElement` / `typeInPage` などのツールを使って Web アプリの自動テストやデバッグができる。
    - 参考: [Build and test web apps with browser agent tools](https://code.visualstudio.com/docs/copilot/guides/browser-agent-testing-guide)
- **コードベース理解・検索（Indexing 等）**
  - **Cursor**
    - プロジェクトを開くと自動でコードベースをインデックスし、セマンティック検索や Agent のコード参照に活用。
    - `.cursorignore` や `.gitignore` を考慮しつつ、定期的に再インデックスされる。
    - 参考: [Codebase indexing | Cursor Docs](https://cursor.com/help/customization/indexing), [Semantic & Agentic Search | Cursor Docs](https://cursor.com/docs/context/codebase-indexing)
  - **GitHub Copilot**
    - Copilot Chat が参照するコンテキストは VS Code 側のチャットセッション／開いているファイル／ワークスペースに依存し、Cursor のように「Indexing」という名前の機能は前面には出ていない。
    - ただし GitHub 上では Copilot Spaces や GitHub Models などで高度なコンテキスト管理が可能。
    - 参考: [About GitHub Copilot Spaces](https://docs.github.com/en/copilot/concepts/context/spaces), [GitHub Models overview](https://docs.github.com/en/github-models)
- **モデル選択**
  - **Cursor**
    - `Auto` や `Composer`（Cursor 独自モデル）、各社のフロンティアモデル（GPT‑5 系、Claude 4.5/4.6、Gemini 3 系など）を用途に応じて選択できる。
    - 参考: [Models & Pricing | Cursor Docs](https://cursor.com/docs/account/pricing)
  - **GitHub Copilot**
    - Copilot Chat / coding agent 両方で「Auto model selection」をサポート。Raptor mini / Claude Sonnet 4.5 / GPT‑5.3‑Codex などから自動選択。
    - Auto 利用時は有料プランで multiplier に 10% 割引も適用される。
    - 参考: [About Copilot auto model selection](https://docs.github.com/en/copilot/concepts/auto-model-selection)

## 2. Rules / Skills / Docs 機能と Copilot での対応関係

### 2-1. Cursor の Rules / Skills / Docs

- **Rules（運用ルールの定義）**
  - `.cursor/rules` や `AGENTS.md` で、プロジェクト／ユーザー／チーム単位のルールを定義し、Agent の「前提」として常に読み込ませられる。
  - チャットから `/create-rule` で半自動的にルールファイルを生成することも可能。
  - 公式: [Rules | Cursor Docs](https://cursor.com/docs/rules)
- **Skills（スキル）**
  - `.agents/skills/` や `.cursor/skills/` に `SKILL.md` とスクリプト／テンプレートを置くことで、Agent に「実行可能なワークフロー」を教えられる。
  - `/create-skill` や `/migrate-to-skills` などで、ルールやコマンドをスキル化できる。
  - 公式: [Agent Skills | Cursor Docs](https://cursor.com/docs/skills), [Agent Skills standard](https://agentskills.io/)
- **Docs（外部ドキュメントのクロール）**
  - `@docs` 機能とクローラで、特定ライブラリや自前ドキュメントサイトをクロールし、チャットから `@docs` として参照できる。
  - 公式: [@docs | Cursor Docs](https://docs.cursor.com/context/%40-symbols/%40-docs), [How does docs crawling work (Forum)](https://forum.cursor.com/t/how-does-docs-crawling-work/264)

### 2-2. Copilot 側で「似たこと」ができるか？

質問:

> Cursorの優位性  
> Rules/Skillsなど“運用の型”を作りやすい  
> Browser useやWeb検索など、開発補助がエディタ内で完結しやすい  
> これはCopilotもできる、という認識はあってますか？

**結論としては「概ね YES だが、体験の作り込みと一体感は Cursor の方が強い」という整理になります。**

- **Rules / Skills に相当するもの**
  - Copilot には Cursor と同じ「Rules」「Skills」という名称の機能はないが、以下の要素を組み合わせることで近いことは可能。
    - **カスタムインストラクション / プロンプトファイル**
      - GitHub 側の「カスタムインストラクション」や VS Code の `.prompt.md` により、Copilot Chat に対する標準的な指示・テンプレートを定義できる。
      - 公式: [Prompt files（VS Code）](https://code.visualstudio.com/docs/copilot/customization/prompt-files)
    - **Copilot Chat skills**
      - VS Code / Visual Studio の Copilot Chat には「skills」という概念があり、特定のタスクに特化したサブエージェント的な存在として機能する。
      - 公式: [GitHub Copilot Chat](https://docs.github.com/en/copilot/using-github-copilot/copilot-chat)
    - **Model Context Protocol (MCP)**
      - MCP サーバー側に「ツール＋プロンプト」を切り出すことで、外部システム連携を含むワークフローを「スキル」に近い形で再利用可能。
      - 公式: [Extending GitHub Copilot Chat with MCP](https://docs.github.com/en/copilot/customizing-copilot/using-model-context-protocol/extending-copilot-chat-with-mcp)
  - ただし、**Cursor ほどファイルシステムと一体となった「Skill パッケージ標準（Agent Skills）」は、Copilot側にはまだ存在しない**。
- **Browser use / Web 検索**
  - **ブラウザ操作**
    - Copilot（VS Code）は「Browser agent tools」により、統合ブラウザを AI が操作可能。
    - UX としては「VS Code の機能＋Copilot」の組み合わせであり、「エディタ＋Agent 一体型」の Cursor とは設計思想が少し違うが、**できることの範囲としては近い**。
    - 公式: [Browser agent tools](https://code.visualstudio.com/docs/copilot/guides/browser-agent-testing-guide)
  - **Web 検索**
    - Copilot Chat で `@github` 参加者などを使った際に、Bing 検索結果を統合できる設定がある（管理者設定依存）。
    - 公式: [Using GitHub Copilot Chat in your IDE](https://docs.github.com/en/copilot/github-copilot-chat/copilot-chat-in-ides/using-github-copilot-chat-in-your-ide)
  - 従って、「**Copilotでもブラウザ操作やWeb検索を使った開発補助は可能。ただし、Cursorの方が最初から AI エージェント開発に振り切った一体感がある**」という理解は妥当です。

## 3. 管理体制とプロダクトの方向性

- **Cursor / Anysphere**
  - 運営: Anysphere（独立企業）
  - ミッション: 「human‑AI programmer（人間＋AIエンジニア）を 10 倍の生産性にする」ことを掲げ、**エディタ体験そのものを AI 前提で再設計**している。
  - 参考: [Series B and Automating Code | Cursor](https://cursor.com/en/blog/series-b)
- **GitHub Copilot / GitHub（Microsoft 傘下）**
  - 運営: GitHub（Microsoft 子会社）
  - 方向性: GitHub.com 上の Issue / PR / Actions と一体化した **エンタープライズ向け AI 開発基盤**。
  - 参考: [What is GitHub Copilot?](https://docs.github.com/en/copilot/copilot-individual/about-github-copilot-individual), [GitHub Copilot Trust Center](https://copilot.github.trust.page/)

あなたのコメント:

> 確かに、GithubCopilotは企業向けの統制機能が強いと思いました。  
> 組織規模が大きい場合はCopilotしか選択肢がなさそう。。。  
> それゆえに開発は他と比べると少しゆっくりになってしまいがち。でも安定はしてるので問題ないとは思うね。

この所感はかなり正確で、

- **Copilot** は
  - プラン／SKU／premium requests（有料リクエスト）で予算と利用上限を厳密に管理できる
  - 組織／エンタープライズでのポリシー管理・監査・モデル制御が充実
  - 開発速度よりも「保守性・安定性・コンプライアンス重視」の進化ペースになりがち
  - 公式: [Plans for GitHub Copilot](https://docs.github.com/copilot/get-started/plans-for-github-copilot), [GitHub Copilot premium requests](https://docs.github.com/en/billing/concepts/product-billing/github-copilot-premium-requests)
- **Cursor** は
  - エディタ自体を自前でコントロールできるため、UX 改良や新機能投入が比較的アグレッシブ
  - 料金はトークンベースで柔軟だが、大規模プロジェクトでは使い方次第で割高に感じる場面もある
  - 公式: [Usage and limits | Cursor Docs](https://cursor.com/help/models-and-usage/usage-limits), [Models & Pricing](https://cursor.com/docs/account/pricing)

という棲み分けになっています。

## 4. 料金モデルのざっくり比較メモ

- **Cursor（個人プラン）**
  - プランごとに「API プール」と「Auto + Composer プール」があり、それぞれに月額の included usage が付与される。
  - 使い切った場合はオンデマンド課金（モデルの API 価格に準拠）。大規模リポジトリで Max Mode などを多用するとコストは上振れしやすい。
  - 公式: [Models & Pricing | Cursor Docs](https://cursor.com/docs/account/pricing), [Usage-based charges](https://cursor.com/help/account-and-billing/overages)
- **GitHub Copilot**
  - プランごとに「premium requests（有料リクエスト）」の月間枠が決まっており、枠内で AI 機能を利用。
  - 高度な推論モデルなどは multiplier により 1 回の利用が 5 倍〜20 倍換算されることがある。
  - 上限を超えて追加利用する場合は 1 リクエストあたり $0.04 で従量課金（ユーザー／組織で予算上限を設定可能）。
  - 公式: [Plans for GitHub Copilot](https://docs.github.com/copilot/get-started/plans-for-github-copilot), [GitHub Copilot premium requests](https://docs.github.com/en/billing/concepts/product-billing/github-copilot-premium-requests)

## 5. まとめ（用途別のざっくり指針）

- **個人開発・少人数チームで「AIエージェント駆動開発」を最速で回したい**
  - **Cursor をメイン**にしつつ、必要に応じて GitHub 側の Copilot coding agent を併用する、という構成が現時点ではもっとも開発体験が良い。
- **大規模組織で GitHub / Actions / セキュリティポリシーと一体で運用したい**
  - **GitHub Copilot（特に Copilot Business / Enterprise）中心**で、組織ポリシー・予算管理・監査ログを前提に設計するのが現実的。
  - 一部のパワーユーザーがローカルで Cursor を併用しつつ、成果物とルールは GitHub 上に集約する形も取りうる。

あなたの最初の所感どおり、

- **Cursor** は「AI エージェント駆動開発に全振りしたエディタ」
- **Copilot** は「GitHub を軸としたエンタープライズ向け AI 開発基盤」

という理解でほぼ間違いありません。
